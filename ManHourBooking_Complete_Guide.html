ManHourBooking - Complete Guide

Staff enter monthly hours; the admin splits them across WBS projects; cost = hours x base rate and is charged against each project's budget. Version 9 (includes dashboard filter memory, logo, and project members).

1. Overview

RoleWhat they do
STAFFSigns up, logs in, submits total hours for the current month, edits them later, sees their own projects and allocation %.
ADMINDashboard (read-only bookings), Projects (budget, expiry, members), Member mapping (hours, allocation split, finalize/reopen month), Staff and rates (base rate history, password reset).

Tech: React 19 + Vite + Tailwind 4 + axios + react-router (frontend); Spring Boot 3 (Java 21), Spring Security with JWT, Spring Data JPA/Hibernate, MySQL (backend).

2. Architecture

Request: React -> axios adds Authorization: Bearer token -> JwtAuthFilter loads the user -> role check (/api/staff/** STAFF, /api/admin/** ADMIN) -> service (transaction) -> DB.

3. Schema diagram

There are no database foreign keys; tables link by value (member_id, wbs_code, YYYY-MM keys). Green border = added in v9.

Reading the lines: a user has many monthly_hours, mappings, bookings and (new) project memberships; a project has many bookings, mappings and members; period_key ties a month to its lock and events; the month's rate comes from the latest base_rate_change whose effective_from is not after that month.

4. Tables in detail

TablePurpose / important columns
app_userEvery login. role is ADMIN or STAFF. Passwords and the security answer are BCrypt hashes; failed_clue_attempts locks the forgot-password flow after 5 tries (app.clue.max-tries). The admin account is created by DataSeeder.
projectOne WBS code per row. Budget invariant: amount_available = amount_allotted - amount_booked. Expired = expiry_date < today (calculated, not stored).
project_member NEWWho may be assigned to which project (the Members column). Gate for Assign and for adding a project row in Edit allocation. Unique pair.
project_member_mappingStanding allocation % per person per project: the default split applied to months submitted from now on. Total per person must stay <= 100.
monthly_hoursThe total hours a person typed for a month (= 100% of that month). One row per person per month.
bookingThe split result. Hours = typed total x %, cost = hours x rate_applied. The rate is stored on the row so later rate changes only touch open months (via repricing).
base_rate_changeCompany-wide hourly rate history. Rate for a month = latest row with effective_from <= month.
period_lock / period_eventMonth-end close. A lock row means finalized (read-only everywhere); events keep the who/when/why of every finalize and reopen.

5. Workflows

5.1 Month life cycle

5.2 Staff submits hours (StaffService.book)

  1. Reject if the month is finalized or hours <= 0 / > 744 or already submitted for this month.
  2. Save monthly_hours.
  3. For each standing mapping: hours = total x %, cost = hours x current rate; create a booking row.
  4. BudgetService.apply moves each project's booked/available by the cost; it fails (with amounts for admin, plain text for staff) if a budget would go negative. All inside one transaction, so a failure leaves nothing half-saved.

5.3 Edit/Assign when the month has no hours (AllocationService.saveDefault) changed

The separate Assign button is gone; Edit/Assign does both. If the employee has no hours for the month, the modal is not locked: it shows the standing allocation, you can set or change the % and add member projects, and the hours column stays disabled at 0. Save calls PUT /allocations/{id}/default: each % is 0-100, 0% removes a project, total <= 100, a project new to the person must be one they are a member of. The % is used the next time hours are added.

5.4 Edit allocation (AllocationService.save)

Admin edits per-project hours/% for one month (finalized months blocked). Sum of hours must be <= typed total. Percentages are derived from hours and trimmed if rounding exceeds 100. Rows with 0 hours or missing are deleted. Budgets change by the cost difference. Optionally the split becomes the new default (syncDefault). New: a project not yet in that month must be one the person is a member of.

5.5 Finalize / reopen (PeriodService)

check reports warnings (staff without hours, unassigned hours, expired projects). finalizeMonth writes period_lock + a FINALIZED event; reopen removes the lock and logs REOPENED with the reason. Everything that writes hours, bookings or rates calls requireOpen/isFinal.

5.6 Base rate change

Preview shows which open months/bookings would be repriced and the cost difference; save reprices open months only, moves project budgets by the difference, and aborts with a message if any project lacks budget. Finalized months are listed as "unchanged".

6. Business rules (cheat sheet)

  • Typed hours = 100% of the month; max 744 h/month.
  • Cost = hours x rate of that month; rate_applied frozen on the row.
  • Project budget: booked + available = allotted at all times; allotted can never go below booked.
  • A person's standing allocation total <= 100%.
  • Finalized month: no hour, allocation or rate change touches it until Reopen.
  • Expired projects still work (no lock) but are flagged with a red badge.
  • Deleting a project removes its bookings, mappings and members; refused if it has bookings in a finalized month.
  • Every table has a Sl No column. Members: allocate only member projects; a member with an allocation or open-month hours cannot be removed.

boolean allocated = mappings.existsByMemberIdAndWbsCode(id, wbsCode);
boolean openHours = projectBookings.stream()
    .anyMatch(b -> b.getMemberId().equals(id) && !periods.isFinal(b.getMonth(), b.getYear()));

The whole method runs in one transaction under the project's row lock, so two admins editing the same project cannot interleave.

10. Project members feature, end to end

  1. Admin: Projects -> Add in the Members column -> tick staff -> Save. PUT /projects/{wbs}/members replaces the list.
  2. Projects list now returns members: [{memberId, name}]; Member mapping reuses that list.
  3. Employee X in P1, P2, P3 -> X's Assign dropdown shows exactly those three.
  4. If someone bypasses the UI, save and saveDefault still answer 400 for non-members.
  5. Upgrading an existing database: SchemaFixer turns every existing allocation/booking pair into a membership so nothing disappears.

11. Run and deploy

# backend (Java 21, MySQL running; DB is created automatically)
cd manhourbooking-backend
set DB_USER=root & set DB_PASSWORD=yourpass & set JWT_SECRET=a-long-random-string-32+chars
mvn spring-boot:run          # http://localhost:8080

# frontend
cd manhourbooking-frontend
npm install
npm run dev                  # http://localhost:5173  (CORS origin must match app.cors.origins)

Before production: change JWT_SECRET and the DB password, set CORS_ORIGINS to your site, and add your logo if you want one.
