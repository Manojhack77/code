BudgetService.java

Keeps every project's budget correct. Everything that spends or refunds money goes through this one method.

Package and imports. r2 is the 2-decimal rounding helper from Money. TreeMap is used so projects are always handled in alphabetical order. Propagation/Transactional control the database transaction.
 15 /**
 16  * Keeps the budget invariant: Available = Allotted - Booked.
 17  * Every change is validated first and applied after, inside the caller's transaction (all or nothing).
 18  */
 19 @Service
 20 public class BudgetService {
The comment states the rule this class protects: Available = Allotted - Booked. @Service makes Spring create one instance and inject it where needed.
 21     private final ProjectRepository projects;
 22 
 23     public BudgetService(ProjectRepository projects) {
 24         this.projects = projects;
 25     }
The class needs only the project repository. It is passed in through the constructor (constructor injection).
 27     /**
 28      * @param deltas  wbsCode -> cost change (positive = more spent, negative = refund)
 29      * @param detailed admins see amounts in error messages; staff must never see budget figures
 30      */
 31     @Transactional(propagation = Propagation.MANDATORY)
 32     public void apply(Map<String, BigDecimal> deltas, boolean detailed) {
apply takes a map of WBS code -> cost change. A positive number means money is spent; a negative number is a refund. detailed decides whether error messages may show amounts: true for admins, false for staff. MANDATORY means it must be called from inside a running transaction; if not, Spring throws an error. That guarantees all-or-nothing.
 33         // Sorted order + row locks: two requests touching the same projects cannot deadlock or overspend.
 34         Map<String, BigDecimal> sorted = new TreeMap<>(deltas);
 35         Map<String, Project> locked = new TreeMap<>();
Copy the changes into a TreeMap (sorted by WBS). Always locking in the same order stops two requests from waiting on each other forever (deadlock). locked will hold the loaded project rows.
 36         for (String wbs : sorted.keySet()) {
 37             locked.put(wbs, projects.lockByCode(wbs)
 38                     .orElseThrow(() -> ApiException.bad("Project " + wbs + " does not exist.")));
 39         }
For each project: lockByCode reads the row with a database write lock, so nobody else can change its budget until this transaction ends. If the project does not exist, the request fails with a clear message.
 40         for (var e : sorted.entrySet()) {
 41             Project p = locked.get(e.getKey());
 42             BigDecimal delta = r2(e.getValue());
 43             if (delta.compareTo(p.getAmountAvailable()) > 0) {
 44                 throw ApiException.bad(detailed
 45                         ? "Not enough budget in " + p.getWbsCode() + ": needs " + delta + " but only "
 46                                 + p.getAmountAvailable() + " is available."
 47                         : "Not enough budget left in " + p.getWbsCode() + ". Ask your administrator.");
 48             }
 49         }
Check phase. Nothing is changed yet. For each project, round the change to 2 decimals and compare with amountAvailable. If the spend is bigger than what is available, stop with an error. Admin message shows the numbers; staff message does not (staff must never see budget figures). A negative delta (refund) is never larger than available, so refunds always pass.
 50         for (var e : sorted.entrySet()) {
 51             Project p = locked.get(e.getKey());
 52             p.setAmountBooked(r2(p.getAmountBooked().add(e.getValue())));
 53             p.setAmountAvailable(r2(p.getAmountAllotted().subtract(p.getAmountBooked())));
 54             projects.save(p);
 55         }
Apply phase. Only reached if every project passed the check. Add the change to amountBooked, then recalculate amountAvailable = allotted - booked (never adjusted separately, so the rule cannot drift), and save. If anything throws before the transaction ends, the database rolls back every project change.

StaffService.book (staff submits monthly hours)

What happens when a staff member presses Submit on the staff page.

100     /**
101      * Saves the typed hours for the month (always, even with no project mapping). Then, for each mapped project,
102      * creates a Booking row: hours_wbs = hours x allocation%, cost = hours_wbs x the base rate in force for the
103      * booked month (saved on the row as rate_applied). The part that is not mapped (100% minus the mapped %)
104      * is not costed now; it is allocated when an administrator maps it.
105      */
106     @Transactional
Documentation: hours are always saved; each mapped project gets a booking row with hours = total x %, cost = hours x rate; the unmapped part is counted later by the admin. @Transactional wraps the whole method: if any line throws, nothing is saved.
107     public MessageResponse book(AuthUser me, BookRequest r) {
108         requireSelf(me, r.memberId());
Entry point. me is the logged-in user (from the token); requireSelf rejects the call if the ID in the request is not the same person (403).
109         if (r.month() == null || r.month() < 1 || r.month() > 12 || r.year() == null || r.year() < 2000 || r.year() > 2100)
110             throw ApiException.bad("Choose a valid month and year.");
111         if (r.hours() == null || r.hours().signum() <= 0) throw ApiException.bad("Enter hours greater than zero.");
112         if (r.hours().compareTo(MAX_HOURS) > 0)
113             throw ApiException.bad("Hours cannot exceed the number of hours in a month (744).");
Input checks: month 1-12, year 2000-2100, hours greater than 0 and at most 744 (31 days x 24 h). Each failure becomes a 400 message shown to the user.
115         periods.requireOpen(r.month(), r.year()); // a finalized month is closed to new hours
116         AppUser u = users.findById(me.memberId()).orElseThrow(() -> ApiException.notFound("Account not found."));
requireOpen refuses a finalized (closed) month. Then load the user record, or fail with 'Account not found'.
117         if (monthly.existsByMemberIdAndMonthAndYear(u.getMemberId(), r.month(), r.year())
118                 || bookings.existsByMemberIdAndMonthAndYear(u.getMemberId(), r.month(), r.year()))
119             throw ApiException.bad("Hours for this month are already submitted. Use View to edit them.");
Duplicate guard: if hours or bookings already exist for this person and month, stop. Editing later is done through View, not by submitting again.
120         List<ProjectMapping> maps = mappings.findByMemberId(u.getMemberId());
121         BigDecimal total = r2(r.hours());
122         List<Booking> rows = new ArrayList<>();
123         Map<String, BigDecimal> deltas = new LinkedHashMap<>();
124         BigDecimal mappedPct = BigDecimal.ZERO;
Load the person's standing allocations (maps). Round the total to 2 decimals. rows will collect the Booking records; deltas collects cost per project for the budget check; mappedPct adds up the % that is actually assigned.
125         if (!maps.isEmpty()) {
126             // One base rate for everyone: the latest change that starts on or before the booked month.
127             String ym = String.format("%04d-%02d", r.year(), r.month());
128             BigDecimal rate = rates.findFirstByEffectiveFromLessThanEqualOrderByEffectiveFromDesc(ym)
129                     .orElseThrow(() -> ApiException.bad("Your account is not ready for booking yet. Ask your administrator."))
130                     .getRate();
Only if the person has allocations: build the month key like 2026-10 and find the latest base rate that starts on or before that month. If no rate exists the account is 'not ready'.
131             for (ProjectMapping m : maps) {
132                 Project pr = projects.findById(m.getWbsCode()).orElse(null);
133                 if (pr == null) continue; // an expired project still takes its share: only a finalized period locks costs
134                 BigDecimal h = r2(total.multiply(m.getAllocationPercentage()).divide(HUNDRED, 4, RoundingMode.HALF_UP));
135                 BigDecimal cost = r2(h.multiply(rate));
For each allocation: load the project (skip if it was deleted). Hours for this project = total x % / 100 (4 decimals during division, then rounded to 2). Cost = hours x rate rounded to 2. Expired projects still get their share because only finalizing locks costs.
136                 Booking b = new Booking();
137                 b.setMemberId(u.getMemberId());
138                 b.setWbsCode(m.getWbsCode());
139                 b.setMonth(r.month());
140                 b.setYear(r.year());
141                 b.setAllocationPercentage(m.getAllocationPercentage());
142                 b.setHoursBooked(h);
143                 b.setRateApplied(rate);
144                 b.setCalculatedCost(cost);
145                 rows.add(b);
146                 deltas.merge(m.getWbsCode(), cost, BigDecimal::add);
147                 mappedPct = mappedPct.add(m.getAllocationPercentage());
148             }
Create the booking row with who, project, month/year, the % used, hours, the rate used (frozen on the row) and the cost. Add the row to the list, add its cost to that project's total in deltas (merge adds if the project appears twice), and add the % to mappedPct.
150         budget.apply(deltas, false); // staff-facing errors carry no amounts; nothing to check when no mapping
Charge all projects at once. If any project lacks budget this throws, and because false is passed, the staff message has no amounts.
151         MonthlyHours mh = new MonthlyHours();

153         mh.setMonth(r.month());
154         mh.setYear(r.year());
155         mh.setTotalHours(total);
156         monthly.save(mh);
157         bookings.saveAll(rows);
Only after the budget passed: save the typed total in monthly_hours and save all booking rows.
158         if (mappedPct.compareTo(HUNDRED) >= 0) return new MessageResponse("Hours submitted successfully!");
159         if (mappedPct.signum() == 0)
160             return new MessageResponse("Hours submitted. You are not assigned to a project yet, so your hours will be "
161                     + "counted when your administrator assigns you.");
162         return new MessageResponse("Hours submitted. " + HUNDRED.subtract(mappedPct).stripTrailingZeros().toPlainString()
163                 + "% of your hours are not assigned to a project yet and will be counted when your administrator assigns them.");
164     }
Choose the reply: fully assigned -> success; nothing assigned -> told hours will be counted when the admin assigns them; partly assigned -> told the remaining % is pending.

AdminService.setMembers (Projects > Members > Add)

Replaces the list of staff who belong to a project. This list controls who can be allocated to the project.

146     public ProjectView setMembers(String wbsCode, MembersRequest r) {
147         Project p = projects.lockByCode(wbsCode).orElseThrow(() -> ApiException.notFound("Project not found."));
148         if (r == null || r.memberIds() == null) throw ApiException.bad("Choose the members.");
Load the project with a write lock (so two admins cannot save at the same moment) or 404. If the request has no list, return 400.
149         Set<String> want = new LinkedHashSet<>();
150         for (String raw : r.memberIds()) {
151             String id = raw == null ? "" : raw.trim();
152             if (!id.isEmpty()) want.add(id);
153         }
Clean the incoming IDs: trim spaces, ignore blanks, and keep each ID once (a LinkedHashSet removes duplicates and keeps order). want is the final list the admin asked for.
154         Map<String, AppUser> staff = users.findByRoleOrderByMemberId(Role.STAFF).stream()
155                 .collect(Collectors.toMap(AppUser::getMemberId, u -> u));
156         for (String id : want)
157             if (!staff.containsKey(id)) throw ApiException.notFound("Staff member " + id + " not found.");
Load all STAFF users into a map by ID. Any wanted ID that is not a staff user (unknown, or an admin) is rejected with 404.
158         List<ProjectMember> current = members.findByWbsCode(wbsCode);
159         Set<String> have = new LinkedHashSet<>();
160         for (ProjectMember pm : current) have.add(pm.getMemberId());
161         List<Booking> projectBookings = bookings.findByWbsCode(wbsCode);
current = members saved now; have = their IDs; projectBookings = all bookings on this project, used to test for hours.
162         List<ProjectMember> toRemove = new ArrayList<>();
163         for (ProjectMember pm : current) {
164             if (want.contains(pm.getMemberId())) continue;
165             String id = pm.getMemberId();
166             boolean allocated = mappings.existsByMemberIdAndWbsCode(id, wbsCode);
167             boolean openHours = projectBookings.stream()
168                     .anyMatch(b -> b.getMemberId().equals(id) && !periods.isFinal(b.getMonth(), b.getYear()));
169             if (allocated || openHours) {
170                 AppUser u = staff.get(id);
171                 throw ApiException.bad((u == null ? id : u.getName()) + " still has an allocation on " + wbsCode
172                         + ". Remove it on the Member mapping page first, then remove the member.");
173             }
174             toRemove.add(pm);
175         }
Find members to remove (in current but not in want). A person cannot be removed if they have a standing allocation on this project, or any hours in a month that is not finalized. In that case the whole save is refused with a message naming them. Otherwise they are added to toRemove. Members whose only hours are in finalized months can be removed; their history stays.
176         members.deleteAll(toRemove);
177         List<ProjectMember> toAdd = new ArrayList<>();
178         for (String id : want) if (!have.contains(id)) toAdd.add(new ProjectMember(wbsCode, id));
179         members.saveAll(toAdd);
Delete the removed rows; create rows for IDs in want that are not in have; save them.
180         return view(p, memberRefs(wbsCode));
181     }
Return the project with its members (the helper sorts them A-Z by name) so the screen refreshes immediately.

AuthProvider wraps the app. useState(getSession) reads a saved session from sessionStorage the first time, so a page refresh keeps you logged in.
  9   const persist = (res) => {

 11     setAuth(res);
 12     return res.user;

persist saves a session (token + user) in sessionStorage, updates state so the screen reacts, and returns the user (used to choose the home page).
 15   const login = async (userId, password) => persist(await api.login({ userId, password }));
 16   // Signing up does not log you in: you are sent to the login page to sign in with the new account.

login calls the API then persists. signup only calls the API: it creates the account and does not log in, so the Signup page sends the user to Login.
 18   const logout = () => {

 20     setAuth(null);
 21   };
logout clears the saved session and the state.
